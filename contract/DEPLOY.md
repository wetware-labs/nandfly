# NandFly deploy procedure (Task 5)

This document is the exact procedure for deploying `NandFly` to BSC. It is
written for Task 5, which is the only task authorized to run any command in
this file against `bsc` or `bscTestnet` -- Task 3 (this contract's
implementation) prepared and dry-ran everything below only against the local
Hardhat network / `localhost`, and made **zero** transactions on any real
chain. Do not run the `--network bsc` / `--network bscTestnet` commands below
until the project's user has explicitly given the go-ahead.

## 0. What gets deployed

`contract/contracts/NandFly.sol`, with `contract/contracts/NandFlyNetlist.sol`
(the 661-gate netlist, auto-generated by `contract/gen_netlist_sol.py` from
`circuit/netlists/full.json`) compiled in. **No constructor arguments** -- the
contract has no owner, no fee configuration, no pausable switch, nothing to
parameterize. `constructor()` takes nothing and only sets the immutable
`bornAt` timestamp.

Before deploying, regenerate the netlist file from the current
`circuit/netlists/full.json` and re-run the full local test suite (parity
included) so you are deploying exactly what was last verified:

```bash
cd nandfly
python contract/gen_netlist_sol.py
python contract/gen_parity_fixture.py
cd contract
npm install         # first time only
npx hardhat compile
npx hardhat test     # all 9 tests, incl. the 4096-pattern parity test, must pass
```

## 1. Network configuration

Already set up in `contract/hardhat.config.js`. Nothing to edit -- just export
environment variables (never commit these):

| Env var | Purpose |
|---|---|
| `BSC_RPC_URL` | HTTPS RPC endpoint for BSC mainnet (chain id 56). E.g. a public endpoint or your own provider (Ankr, NodeReal, QuickNode, ...). |
| `BSC_TESTNET_RPC_URL` | RPC endpoint for BSC testnet (chain id 97), for a dry run with real transactions but fake funds first. |
| `BSC_DEPLOYER_PRIVATE_KEY` | Private key of the deploying wallet. Funded with a small amount of BNB (see gas estimate below) -- this is a plain EOA, not a multisig; there is no on-chain admin role to hand off later, so which wallet deploys is not a long-term trust decision, only a one-time gas payer. |
| `BSCSCAN_API_KEY` | For `hardhat verify` (source verification on BscScan). Free tier is enough. |

None of these are set anywhere in this repo or its `.gitignore`d dirs. Without
them, `--network bsc` fails closed (empty RPC URL / no signer) rather than
silently doing something unexpected.

## 2. Deploy

Dry run locally first (always safe, no real chain touched):

```bash
npx hardhat run scripts/deploy.js
```

Testnet rehearsal (recommended before mainnet -- real transactions, fake
funds; get testnet BNB from a BSC testnet faucet):

```bash
export BSC_TESTNET_RPC_URL=...
export BSC_DEPLOYER_PRIVATE_KEY=...
npx hardhat run scripts/deploy.js --network bscTestnet
```

Mainnet (Task 5, after explicit go-ahead):

```bash
export BSC_RPC_URL=...
export BSC_DEPLOYER_PRIVATE_KEY=...
npx hardhat run scripts/deploy.js --network bsc
```

`scripts/deploy.js` prints the deployed address, the deployment tx hash, gas
used, and (on `bsc`/`bscTestnet`) the exact next-step commands for steps 3-4
below with the address already filled in.

## 3. Verify on BscScan

```bash
npx hardhat verify --network bsc <DEPLOYED_ADDRESS>
```

No constructor arguments to pass (the constructor takes none). This publishes
`NandFly.sol` + `NandFlyNetlist.sol` source so anyone can read the embedded
netlist bytes and the "no admin keys" claim directly on BscScan, not just
trust this repo.

## 4. Post-deploy parity spot-check (against the LIVE address)

`scripts/parity_check.js` re-checks `swat()` on the deployed contract against
`contract/fixtures/parity_4096.json` (the same fixture the local test suite
checks all 4096 patterns against, generated from `circuit/gates.py`). By
default it checks a spread-out 200-pattern sample plus both edge cases
(stimulus `0` and `4095`) via `eth_call` (free, no gas spent) -- this confirms
the bytecode that actually got deployed and verified matches what was tested,
without re-spending a full 4096-call RPC budget on a metered endpoint. Pass
`NANDFLY_FULL=1` to check all 4096 instead (still free -- `swat()` is a `pure`
function, calls are `eth_call`, not transactions).

```bash
NANDFLY_ADDRESS=<DEPLOYED_ADDRESS> npx hardhat run scripts/parity_check.js --network bsc
# or, for full coverage:
NANDFLY_ADDRESS=<DEPLOYED_ADDRESS> NANDFLY_FULL=1 npx hardhat run scripts/parity_check.js --network bsc
```

The script also sanity-checks `GATE_COUNT() == 661` before spending any calls
on the actual sample, and exits non-zero with a printed mismatch list on any
disagreement.

## 5. Gas / cost estimates

Measured on the local Hardhat network (solc 0.8.24, optimizer 200 runs; see
`.superpowers/sdd/nandfly-mvp/task-3-report.md` for the full run):

| Item | Gas |
|---|---|
| Deployment (`NandFly.deploy()`) | 1,134,857 |
| `swatTx()` (a full stimulus pattern, min/avg/max across sampled patterns) | 455,066 / 479,420 / 489,580 |
| `swat()` (view/`eth_call`; free in normal use -- shown here as its gas-equivalent cost if it were a state-changing call) | ~443,300-443,627 |

BSC gas price and BNB/USD both move; here is the arithmetic at a few
illustrative gas prices (BNB price fixed at an example $600 for the USD
column -- **re-check both numbers at actual deploy time**, e.g. via
https://bscscan.com/gastracker and any BNB price source):

| Gas price | Deploy cost (BNB) | Deploy cost (USD @ $600/BNB) | Avg `swatTx()` cost (BNB) | Avg `swatTx()` cost (USD) |
|---|---|---|---|---|
| 1 gwei | 0.001135 | $0.68 | 0.000479 | $0.29 |
| 3 gwei | 0.003405 | $2.04 | 0.001438 | $0.86 |
| 5 gwei | 0.005674 | $3.40 | 0.002397 | $1.44 |

This is consistent with the project ledger's earlier "~$3" budget line for
the Layer-1 contract's gas footprint (see
`.superpowers/sdd/nandfly-mvp/progress.md`), and leaves a wide margin under
the project's overall $50 budget cap.

## 6. What Task 5 should NOT need to touch

- The netlist encoding (`contract/gen_netlist_sol.py`) -- only re-run it if
  `circuit/netlists/full.json` changes.
- `hardhat.config.js` -- network config is already complete; only env vars
  need to be supplied.
- `contract/contracts/NandFly.sol` / `NandFlyNetlist.sol` -- these are the
  audited, parity-tested artifacts. If a change is needed here, treat it as a
  new implementation change (re-run the full test suite, including the
  4096-pattern parity test) before any real-network deploy, not a Task 5
  on-the-fly edit.
